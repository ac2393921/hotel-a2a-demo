- 対応Issue: [#21 専用UIの画面要件とワイヤーフレームを決める](https://github.com/ac2393921/hotel-a2a-demo/issues/21)
- 親Story: [#8 専用画面でゲスト対応とA2Aの流れを見せる](https://github.com/ac2393921/hotel-a2a-demo/issues/8)
- 親Epic: [#3 専用UIを作り込む](https://github.com/ac2393921/hotel-a2a-demo/issues/3)
- 更新日: 2026-10-07

## 目的

ゲストとの会話と、Front Deskから部署Agentへ依頼して結果を受け取る流れを1画面で確認できるようにする。変更案は承認前の提案として表示し、承認後の結果と明確に区別する。

## 対象範囲

- ゲストとFront Deskの会話履歴、追加質問、メッセージ入力。
- Restaurant Agentの変更案と、明示的な承認・拒否操作。
- Maintenance、Housekeeping、Restaurantの能力情報と、依頼された部署のTask状態・結果。
- 一部Agentが失敗した場合の失敗表示と、取得できた部分回答。
- デスクトップとモバイルのレイアウト、キーボード操作、読み上げ可能な状態通知。

対象外:

- Agentの内部推論、プロンプト、非公開の内部状態の表示。
- 実在の予約やホテルシステムとの接続。
- A2A上で送受信されていない進捗を推測で表示すること。

## 情報設計

### 画面領域

| 領域 | 内容 |
| --- | --- |
| ヘッダー | デモ名、接続状態、現在の会話がデモ用であること |
| 会話 | GuestとFront Deskの発言、追加質問、提案カード、最終回答 |
| Agent一覧 | 3部署の名称、担当能力、今回の依頼有無、Task状態 |
| Taskタイムライン | A2A依頼の受付、状態更新、完了・失敗、受信した結果 |
| 入力欄 | メッセージ送信。処理中の二重送信を防ぐ状態表示 |

部署一覧には全3部署を表示し、今回依頼されなかったAgentは「今回の依頼なし」とする。依頼対象と実行状態を混同させない。

### 状態と表示文言

| 状態 | 表示 | 振る舞い |
| --- | --- | --- |
| 待機中 | メッセージ入力を促す | Agent一覧は能力情報を表示し、Taskはまだ表示しない |
| 依頼受付 | 受付済み | A2Aの受付を確認できた場合だけ表示 |
| 処理中 | 対応中 | Agentから処理中状態を受信した場合だけ表示 |
| 完了 | 完了 | AgentのTask完了と応答を表示 |
| 失敗 | 接続または処理に失敗 | 失敗した部署を明示し、得られた他部署の結果は残す |
| 追加情報待ち | Front Deskからの質問 | Guestが回答できる会話メッセージとして表示 |
| 承認待ち | 変更案を確認してください | Restaurantの提案と承認・拒否操作を表示。予約変更済みとは表示しない |
| 承認済み | 変更結果を受信 | Restaurant Agentから確定結果を受け取った後にのみ表示 |
| 拒否済み | 提案を取り下げました | Restaurant Agentから拒否結果を受け取った後にのみ表示 |

受信した状態だけを画面へ反映する。途中状態が届かなかった場合に、受付や処理中の履歴を補完・捏造しない。エラー文は原因の内部詳細を漏らさず、利用者が把握できる説明にする。

## 主要操作

### 会話と部署への委譲

1. Guestがメッセージを送る。
2. 入力欄を送信中状態にし、重複送信を防ぐ。
3. Front Deskの追加質問または回答を会話に追加する。
4. A2Aイベントを受信した部署だけ、Agent一覧とTaskタイムラインに表示する。
5. 部署結果を受信した順に反映し、最後にFront Deskの集約回答を表示する。

### 変更案の承認・拒否

1. Restaurantの変更案を「提案・未確定」と表示する。
2. 提案カードに現在時刻、変更候補時刻、承認、拒否を表示する。
3. Guestが承認または拒否を押すと、その判断を通常の会話メッセージとしてFront Deskへ送る。
4. Restaurant Agentから結果を受信するまではボタンを再操作できないようにし、予約状態を確定表示しない。
5. 結果を受信した後にだけ、承認済みまたは拒否済みへ切り替える。

### 部分失敗

- 失敗Agentのカードに失敗状態と短い説明を表示する。
- 完了Agentの結果は消さずに表示し、回答全体に「一部の部署から応答を得られませんでした」と示す。
- 部署が未選択の場合は失敗扱いにせず「今回の依頼なし」とする。

## デスクトップ・ワイヤーフレーム

画面幅が広い場合は会話とAgent進行を並べて表示する。会話を主領域とし、部署別状態を隣の領域で追える構成にする。

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Hotel A2A Demo                                      ローカルデモ / 接続中 │
├─────────────────────────────────────────────┬────────────────────────────┤
│ ゲストとの会話                              │ Agentの処理状況            │
│                                             │                            │
│ Guest                                       │ Maintenance                │
│ エアコンが壊れていて、19時から予約…        │ 完了  修理は夕食後         │
│                                             │ Taskタイムライン ▾         │
│ Front Desk                                  │                            │
│ 3部署へ確認します。                         │ Housekeeping               │
│                                             │ 完了  代替部屋あり         │
│ Restaurant Agentからの提案                  │ Taskタイムライン ▾         │
│ 19:00 → 20:00                               │                            │
│ 状態: 未確定・承認待ち                      │ Restaurant                 │
│ [変更を承認] [提案を拒否]                  │ 承認待ち  20:00を提案      │
│                                             │ Taskタイムライン ▾         │
│ ┌───────────────────────────────────────┐  │                            │
│ │ メッセージを入力…              [送信] │  │ 部分失敗時はこの位置に     │
│ └───────────────────────────────────────┘  │ 失敗部署と部分結果を表示   │
└─────────────────────────────────────────────┴────────────────────────────┘
```

Taskタイムラインの展開例:

```text
14:03:12  Restaurant Agentへ依頼を送信
14:03:12  Task受付
14:03:13  Task完了
14:03:13  20:00への変更案を受信
```

時刻は画面またはサーバーがイベントを受信した時刻とする。Agent内部の処理時刻として誤認させない。

## モバイル・ワイヤーフレーム

狭い画面では1列にし、会話を先に、Agent進行を続けて表示する。固定幅の横並びや横スクロールを要求しない。

```text
┌──────────────────────────┐
│ Hotel A2A Demo   接続中  │
├──────────────────────────┤
│ ゲストとの会話            │
│                          │
│ Guest                    │
│ エアコンが壊れていて…    │
│                          │
│ Restaurantの変更案       │
│ 19:00 → 20:00            │
│ 未確定・承認待ち          │
│ [変更を承認]             │
│ [提案を拒否]             │
│                          │
│ [メッセージを入力…]      │
│ [送信]                   │
├──────────────────────────┤
│ Agentの処理状況           │
│ Maintenance   完了       │
│ Housekeeping  完了       │
│ Restaurant    承認待ち   │
│ [Taskタイムラインを表示] │
└──────────────────────────┘
```

## アクセシビリティ要件

- ページ、会話、Agent状態を見出しとランドマークで区別する。
- 送信、承認、拒否、タイムライン展開をキーボードだけで操作できる。
- フォーカス位置を視認可能にし、処理終了後に予期しない位置へ移動させない。
- 入力欄と各操作にプログラム上のラベルを付ける。
- 状態を色だけで伝えず、テキストとアイコンまたは形を併用する。
- 新しい応答・状態は適切なライブ領域で通知する。長いタイムライン全体を毎回読み上げない。
- エラーと承認結果は発生位置に関連付けて読み上げ可能にする。
- デスクトップとモバイルで文字、操作領域、コントラストを確認する。

## A2A境界と表示データ

- GuestのメッセージはFront Deskだけに送り、ブラウザーから部署Agentへ直接送信しない。
- 画面に表示するAgent情報はAgent Cardの公開能力情報と、A2A Taskの状態・メッセージ・artifactなど受信したデータに限る。
- 内部推論、内部メモリ、秘密情報、未受信の進捗は表示しない。
- 部署名、Task ID、状態、表示用応答を会話とTaskタイムラインで関連付ける。Task IDは詳細表示に置き、主表示を読みにくくしない。
- Guestの発話をHTMLとして解釈せず、テキストとして安全に表示する。
