# Restaurant予約状態の運用

次期予約業務のInMemoryRepositoryはRestaurantの単一プロセスで使う。複数worker・複数プロセスへの分散と永続化は対象外。更新はtransactionの排他境界内で行い、例外・キャンセル時は予約と提案を同時に巻き戻す。

HotelClockはAsia/Tokyoを既定とする。demo_repositoryは起動時点の翌日に架空の初期予約を作る。通常予約、個室満席、同じゲストの複数予約が含まれる。再生成・プロセス再起動で初期状態に戻り、他インスタンスと状態を共有しない。初期データに実在するゲスト情報は使わず、Repository自体はログを出力しない。

現段階ではアダプターの提供のみで、既存Restaurantサービスへの接続はTask #53以降で行う。リセット用の公開APIは設けない。
