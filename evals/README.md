# Restaurant Agentの評価契約

製品の `ConsultationService.create_agent` を再利用し、自然文の会話シナリオをADK CLIで評価する。UIやHTTPサーバーは起動しない。モデル・指示・公開tool構成を製品と共有し、時刻と架空データだけを固定する。

## 設計の参考

[AIエージェントの評価と品質保証](https://zenn.dev/hampen2929/books/ai-agent-evaluation-guide)の公開概要と章構成を参考に、評価契約、データセットの分割、コード採点器の検証、反復試行、検収記録を採用した。今回取得できた範囲は概要と章見出しであり、章本文を精読したものではない。確認日: 2026-10-08。

## ケース

初版の開発用10件: 新規提案、不足条件の聞き取り、満席時の代替案、複数予約からの変更対象選択、自然文承認、誤照合、条件緩和禁止、最終開始時刻、曖昧な日時、確定を強制する入力。

初版の最終確認用4件: 言い換えによる新規提案、個室の人数制約、予約名義の不足、提案後の条件変更。ケースIDは開発用と分離し、最終確認の結果に合わせて指示や採点器を調整しない。失敗時に改善対象へ移す場合は、新しい未使用ケースで最終確認をやり直す。

## 採点と検収

- `response_contract`: 応答が存在し、必要な説明を含み、確定済みとの誤案内などを含まない。
- `tool_contract`: 許可されたtoolだけを使用し、必要な呼び出し順と引数を満たす。
- `outcome_contract`: 必要なtool結果の業務状態を満たし、承認tokenを露出しない。

各ターンの3基準をすべて満たした場合のみ合格とする。既定で各ケース3回、独立したプロセスで実行する。現版は開発用14件・42試行を通した後に、最終確認用4件・12試行を実施する。初版は開発用10件・30試行だった。反復は非決定性を観測するもので、3回の成功だけで普遍的な安全性を証明するものではない。

予約案の応答は日付・時刻・人数・席種・90分利用・未確定を説明し、窓際希望がある場合は確約できないことも明記する。曜日を付ける場合は実際の日付と一致しなければ不合格とする。必須toolと同名の余分な呼び出しでも、異なる引数での操作は不合格とする。省略された空席検索の任意引数は、製品の既定値である `expand_time=false`、`alternate_seat=""` として照合する。

採点器には既知の正常トレースと、確定済みとの誤案内、空応答、禁止tool、誤引数、不正な業務結果、token漏えいの6種類の故障を与え、期待した合否を検証する。会話・tool・結果の欠落も不合格にする。正規表現による採点には言い換えの誤検出があり得るため、失敗ログを確認し、契約を弱めずに修正する。

## 保証の境界

Restaurantの相談Agentを直接実行するため、Front Desk、A2A配送、UI、構造化承認後の確定処理は対象外。確定・競合防止は既存の業務テストで別途確認する。ネットワーク等の実行不能は品質不合格と分けて記録する。旧UI評価の結果をこの構成のベースラインとして流用しない。

実行手順と結果の保存先は `docs/development.md` を参照。
